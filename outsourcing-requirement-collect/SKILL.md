<core_principle>
## 核心原则：专业完善需求

客户描述的需求往往不完整，作为专业开发者，我们需要：

1. **主动发现** - 客户没说但实际需要的功能
2. **专业补充** - 基于行业经验补充需求
3. **风险预警** - 技术可行性、潜在风险
4. **引导确认** - 列出待确认事项

```
客户描述 → 专业分析 → 需求补充 → 客户确认 → 完整需求
```

**注意：本技能只负责收集和完善需求，不进行价格评估。**
</core_principle>

   - 核心功能有哪些？

   - 对照行业功能清单，发现遗漏功能
   - 分析技术可行性
   - 识别潜在风险
   - **不做价格评估**

4. **创建项目目录** ⭐ 必须执行
   - 使用 mcp_digital-employee_file_create_dir 创建目录：
   - docs/工作空间/01-项目管理/[项目名]/
   - docs/工作空间/01-项目管理/[项目名]/01-需求/

5. **生成需求收集表文档** ⭐ 必须执行
   - 使用 Write 工具生成文件：
   - 路径：docs/工作空间/01-项目管理/[项目名]/01-需求/需求收集表.md
   - 包含客户描述的需求
   - 标注专业补充的需求（需确认）
   - 列出待确认事项
   - **不包含价格信息**

6. **生成客户确认表** ⭐ 动态生成
   - 使用 Write 工具生成文件：
   - 路径：docs/工作空间/01-项目管理/[项目名]/01-需求/客户确认表.md
   - **内容来源**：根据需求收集表的"待确认事项"动态生成
   - **格式要求**：
     - 使用 `- [ ] A. 选项` 格式，方便电子确认
     - 每个问题独立成段，选项清晰
     - 多选题标注"（可多选）"
     - 需要填写的预留下划线
   - **生成规则**：
     - 遍历需求收集表中的待确认事项
     - 将每个待确认事项转换为选择题
     - 按模块分组（用户体系、核心业务、技术需求等）
     - 问题数量控制在30-50题

7. **客户确认** ⭐ 必须执行
   - 使用 AskUserQuestion 询问客户确认需求收集表
   - 确认选项：
     - "确认完整，继续下一步" → 进入下一阶段
     - "需要补充细节" → 根据反馈修改
     - "暂不确认" → 等待

8. **验证完成**
   - [ ] 收集了项目背景
   - [ ] 明确了目标用户
   - [ ] 列出了核心功能
   - [ ] 补充了专业建议
   - [ ] 标注了待确认事项
   - [ ] 创建了项目目录
   - [ ] 生成了需求收集表.md文件
   - [ ] 生成了客户确认表.md文件 ⭐新增
   - [ ] 客户已确认
</action>

## 需求确认问题清单

> 用于引导客户完善需求

### 业务相关

1. 用户角色有哪些？每个角色的权限是什么？
2. 核心业务流程是怎样的？
3. 数据从哪里来？需要对接哪些系统？
4. 预期用户量/并发量是多少？
5. 是否需要移动端？小程序还是App？

### 技术相关

1. 是否有现有系统？需要迁移数据吗？
2. 是否有技术栈偏好？
3. 是否需要对接第三方服务？（支付、短信、地图等）
4. 对安全性有什么要求？
5. 是否需要支持多语言？

### 运营相关

1. 是否需要数据统计和报表？
2. 是否需要运营后台？
3. 是否需要消息推送功能？
4. 是否需要SEO优化？
5. 是否需要分享和推广功能？

### 时间相关

1. 预期上线时间？
2. 是否有硬性截止日期？
3. 是否接受分期开发？
</requirement_questions>
