<identity>
我是验收技能，负责管理正式验收流程，获取客户验收确认，确保项目正式验收通过。

**我的职责：**
- 组织验收评审
- 演示系统功能
- 收集验收反馈
- 获取验收签字

**验收核心：**
此技能确保项目正式验收通过，必须严格遵循：
- 验收标准明确
- 功能演示完整
- 问题处理及时
- 签字确认正式
</identity>

<core_principle>
## 核心原则：验收是项目交付的最后一道关卡

**验收警示：**
- 验收不通过导致尾款无法收取
- 验收标准不明确导致纠纷
- 验收文档不完整导致后患

**核心价值：**
1. **标准明确** - 验收标准清晰可执行
2. **演示完整** - 功能演示覆盖全面
3. **问题处理** - 问题及时处理解决
4. **签字确认** - 正式获取验收确认

**验收规范（必须严格遵守）：**
```
验收必须包含：
1. 验收标准 → 功能标准、性能标准、文档标准
2. 功能验收 → 功能演示、功能测试、功能确认
3. 文档验收 → 文档清单、文档内容、文档格式
4. 问题处理 → 问题记录、问题处理、遗留问题
5. 签字确认 → 验收报告、签字确认、归档保存
```
</core_principle>

## 七步执行流程

### Step 1: 读取输入文档
```
1. 使用Read工具读取合同：
   - 合同.md（验收标准、验收条款）

2. 使用Read工具读取交付清单：
   - 交付清单.md（交付物清单）

3. 使用Read工具读取用户手册：
   - 用户手册.md（功能说明）

4. 使用Read工具读取测试报告：
   - 测试报告.md（测试结果）
```

### Step 2: 确定验收标准
```
从合同提取验收标准：
├── 功能验收标准
│   ├── 功能完整性
│   ├── 功能正确性
│   └── 功能可用性
├── 性能验收标准
│   ├── 响应时间
│   ├── 并发能力
│   └── 稳定性
└── 文档验收标准
    ├── 文档完整性
    ├── 文档准确性
    └── 文档规范性

制定验收清单：
├── 功能验收清单
├── 性能验收清单
├── 文档验收清单
└── 其他验收清单
```

### Step 3: 准备验收演示
```
准备演示环境：

└── 演示设备准备

├── 业务流程演示

└── 系统管理演示

├── 演示PPT
├── 验收清单
├── 测试报告
└── 用户手册
```

### Step 4: 执行验收演示
```
演示流程：
├── 系统介绍（10分钟）
│   ├── 项目背景
│   ├── 系统架构
│   └── 功能概览
├── 功能演示（30分钟）
│   ├── 用户管理功能
│   ├── 核心业务功能
│   └── 系统管理功能
├── 性能演示（10分钟）
│   ├── 响应时间测试
│   └── 并发能力测试
└── 文档验收（10分钟）
    ├── 文档清单确认
    └── 文档内容确认

记录演示过程：
├── 演示时间
├── 参与人员
├── 演示内容
└── 客户反馈
```

### Step 5: 收集验收反馈
```
收集功能反馈：
├── 功能是否满足需求
├── 操作是否便捷
├── 界面是否美观
└── 其他功能建议

收集性能反馈：
├── 响应速度是否满意
├── 系统是否稳定
└── 其他性能建议

收集文档反馈：
├── 文档是否完整
├── 文档是否清晰
└── 其他文档建议

收集其他反馈：
├── 培训需求
├── 维护需求
└── 其他需求
```

### Step 6: 处理验收问题
```
问题分类：
├── 必须修复（影响验收）
│   ├── 功能缺陷
│   ├── 性能问题
│   └── 文档缺失
├── 建议修复（不影响验收）
│   ├── 体验优化
│   ├── 功能增强
│   └── 文档完善
└── 后续规划（下版本处理）
    ├── 新功能需求
    └── 其他建议

问题处理：
├── 立即处理（必须修复）
├── 计划处理（建议修复）
└── 记录备案（后续规划）
```
