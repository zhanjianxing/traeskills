## 🎯 外包流程 Skills 详解

### 阶段一：需求沟通

#### 1.1 需求收集 `outsourcing-requirement-collect`

**前置条件**：无
**触发场景**：客户提及"需求收集"、"项目背景"、"了解需求"

**输入**：客户描述（口头/文字）
**输出**：
- `docs/工作空间/01-项目管理/[项目名]/01-需求/需求收集表.md`
- `docs/工作空间/01-项目管理/[项目名]/01-需求/客户确认表.md`

**核心能力**：
- 收集项目背景、目标用户、项目愿景
- 基于行业经验主动补充遗漏功能
- 生成客户确认表进行需求确认

**下一步**：`outsourcing-requirement-research`（必选）

---

#### 1.2 需求调研 `outsourcing-requirement-research`

**前置条件**：需求收集表.md 存在
**触发场景**：客户确认需求后、竞品分析、用户研究

**输入**：
- `需求收集表.md`
- 项目类型

**输出**：
- `调研分析报告.md`

**核心能力**：
- 竞品分析（3-5个主要竞品）
- 用户研究（用户画像、需求、痛点）
- 市场机会与差异化分析

**下一步**：`outsourcing-requirement-organize`

---

#### 1.3 需求沟通记录 `outsourcing-requirement-record`

**前置条件**：需求收集或调研过程中
**触发场景**：记录每次需求沟通会议

**输入**：沟通会议内容
**输出**：`沟通记录.md`

**核心能力**：
- 记录讨论要点和决策
- 跟踪待办事项
- 保持沟通可追溯

---

#### 1.4 需求整理 `outsourcing-requirement-organize`

**前置条件**：
- 需求收集表.md 存在
- 调研分析报告.md 存在

**触发场景**：客户确认调研报告后、整理功能清单

**输入**：
- `需求收集表.md`
- `调研分析报告.md`

**输出**：`需求清单.md`

**核心能力**：
- 按业务子模块组织功能
- 定义API接口（路径、方法、参数）
- 整理非功能需求（性能、安全、兼容性）
- 统计接口数量（核心/重要/辅助）

**下一步**：
- 客户确认后 → `outsourcing-quotation-generate`（生成报价）
- 或进入开发阶段 → 选择开发技能

---

### 阶段二：商务流程

#### 2.1 报价生成 `outsourcing-quotation-generate`

**前置条件**：需求清单.md 存在（终版）
**触发场景**：客户确认需求清单后

**输入**：
- `需求清单.md`
- 客户类型判断

**输出**：`项目报价书.md`

**核心能力**：
- AI驱动智能报价（传统模式 vs 价值模式）
- 全流程人天估算（AI效率提升50-70%）
- 三种报价模式：
  - **传统型**：固定总价+预付款
  - **价值型**：价值定价+里程碑付款+成果分成
  - **观望型**：双方案选择

**下一步**：`outsourcing-quotation-confirm`

---

#### 2.2 报价确认 `outsourcing-quotation-confirm`

**前置条件**：
- 需求清单.md 存在
- 项目报价书.md 存在

**触发场景**：整合报价和需求生成确认书

**输入**：
- `需求清单.md`
- `项目报价书.md`

**输出**：`报价确认书.md`（双方签字版本）

**核心能力**：
- 整合功能清单和报价明细
- 明确验收标准和交付内容
- 生成可签字的正式确认书
- **具有法律效力**

**下一步**：`outsourcing-contract-generate`

---

#### 2.3 合同生成 `outsourcing-contract-generate`

**前置条件**：报价确认书.md 存在（双方已签字）
**触发场景**：生成正式项目合同

**输入**：
- `报价确认书.md`
- 合同模板

**输出**：`项目合同.md`

**核心能力**：
- 生成正式法律合同
- 包含所有商务条款
- 知识产权和保密条款

**下一步**：`outsourcing-contract-review`

---

#### 2.4 合同审核 `outsourcing-contract-review`

**前置条件**：项目合同.md 存在
**触发场景**：审核合同法律合规性

**输入**：`项目合同.md`

**输出**：审核报告

**核心能力**：
- 法律合规性检查
- 风险点识别
- 修改建议

---

### 阶段三：交付验收

#### 3.1 交付清单 `outsourcing-delivery-list`

**前置条件**：项目合同存在
**触发场景**：项目开发完成、准备交付

**输入**：
- `需求清单.md`
- `报价确认书.md`
- 项目成果物

**输出**：`交付清单.md`

**核心能力**：
- 列出所有交付物
- 源代码、文档、账号密码
- 验收标准对照

**下一步**：`outsourcing-acceptance`

---

#### 3.2 项目验收 `outsourcing-acceptance`

**前置条件**：交付清单.md 存在
**触发场景**：客户验收阶段

**输入**：
- `交付清单.md`
- 项目成果物

**输出**：`验收报告.md`

**核心能力**：
- 对照需求清单验证功能
- 记录验收结果
- 遗留问题处理

**下一步**：`outsourcing-project-summary`

---

#### 3.3 项目总结 `outsourcing-project-summary`

**前置条件**：项目验收通过
**触发场景**：项目正式完成

**输入**：
- 项目全过程文档
- 验收报告

**输出**：`项目总结.md`

**核心能力**：
- 项目回顾与复盘
- 经验教训总结
- 后续维护建议

### 后端开发

#### `vibe-microservice-dev` - 微服务开发

**前置条件**：需求清单
**适用场景**：
- 大规模分布式系统
- 高并发、高可用需求
- 多团队协作的大型项目

**技术栈**：
- Spring Boot 3.2 / Spring Cloud Alibaba 2023.0.x
- Nacos 2.x（注册/配置）
- OpenFeign + LoadBalancer（服务调用）
- Sentinel 1.8.x（熔断限流）
- Seata 1.7.x（分布式事务）
- RocketMQ 5.x（消息队列）
- MySQL 8.0 + MyBatis-Plus 3.5.x
- JetCache 2.7.x + Redis 7.x
- Spring Security 6.x + JWT

**开发流程**（十步法）：
```
Step 0: 读取需求清单 → Step 1: 参数校验 → Step 2: 幂等校验+业务校验
→ Step 3: 数据操作 → Step 4: 缓存策略 → Step 5: 服务调用(Feign)
→ Step 6: 限流熔断(Sentinel) → Step 7: 分布式事务(Seata)
→ Step 8: 消息队列/事件发布 → Step 9: 结果封装
```

**知识库**：
- 微服务架构设计
- Nacos服务注册与配置
- 网关设计
- JetCache三级缓存
- Feign+Sentinel服务调用
- Seata分布式事务
- RocketMQ消息队列
- 链路追踪
- 微服务安全

---

#### `vibe-monolithic-dev` - 单体开发

**前置条件**：需求清单
**适用场景**：
- 中小型项目（团队<10人）
- 快速迭代的创业项目
- 不需要微服务复杂度的业务系统
- 需要分布式部署的企业内部系统

**技术栈**：
- Spring Boot 3.2 / Java 17+
- MyBatis-Plus 3.5.x
- JetCache 2.7.x
- Spring Security 6.x + JWT
- Bucket4j/RateLimiter（限流）

**架构理念**：空壳Server + 业务模块化

**开发流程**（十步法）：
```
Step 0: 读取需求清单 → Step 1: 参数校验 → Step 2: 幂等校验+业务校验
→ Step 3: 数据操作 → Step 4: 缓存策略 → Step 5: 事务管理
→ Step 6: 事件发布 → Step 7: 结果封装 → Step 8: 异常处理
→ Step 9: 索引检查
```

**vs 微服务区别**：
| 对比项 | 单体 | 微服务 |
|--------|------|--------|
| 事务范围 | 本地事务 | 分布式事务 |
| 调用方式 | JVM内方法调用 | HTTP/RPC跨进程调用 |
| 适用规模 | 中小型 | 大型分布式 |

**知识库**：
- 单体架构设计
- 模块化设计
- 缓存策略
- 安全认证
- 性能优化

---

#### `vibe-python-dev` - Python开发

**前置条件**：需求清单
**适用场景**：
- Web API服务（FastAPI/Flask）

**知识库**：
- 项目架构设计

- 测试规范

**前置条件**：代码已提交到Git
**触发场景**：部署到服务器、更新代码、管理生产环境

**核心原则**：

```

→ 构建 → 部署 → 健康检查
```

**支持**：
- GitHub Actions CI/CD
- Docker/Kubernetes
- 回滚操作

## 🔗 Skills 组合使用指南

### 场景1：全新外包项目（从需求到交付）

```
需求收集 → 竞品分析 → 需求整理 → 报价生成 → 报价确认
    → 合同生成 → 合同审核 → 开发 → 测试 → 部署
    → 交付清单 → 验收 → 项目总结
```

**技能调用顺序**：
1. `outsourcing-requirement-collect` - 需求收集
2. `outsourcing-requirement-research` - 竞品分析
3. `outsourcing-requirement-organize` - 需求整理
4. `outsourcing-quotation-generate` - 报价生成
5. `outsourcing-quotation-confirm` - 报价确认
6. `outsourcing-contract-generate` - 合同生成
7. [开发技能选择] - 技术选型
8. `vibe-test` - 功能测试
9. `devops-deploy` - 部署上线
10. `outsourcing-delivery-list` - 交付清单
11. `outsourcing-acceptance` - 项目验收
12. `outsourcing-project-summary` - 项目总结

---

### 场景2：技术选型决策

根据项目特征选择开发技能：

| 项目特征 | 推荐技能 | 原因 |
|----------|----------|------|
| 大型分布式/高并发/多团队 | `vibe-microservice-dev` | 微服务架构支持 |
| 中小型/快速迭代/内部系统 | `vibe-monolithic-dev` | 简单高效 |
| Python技术栈/Web API | `vibe-python-dev` | Python生态 |
| 需要移动端App | `mobile-app-dev` + 后端技能 | 跨平台开发 |
| 前端界面为主 | `frontend-ui-design` | UI设计规范 |

## 🎓 核心原则

### 外包流程原则

1. **客户驱动**：所有流程以客户需求为中心
2. **文档先行**：每个阶段必须有文档输出
3. **确认机制**：关键节点必须客户确认
4. **法律保障**：报价确认书和合同具有法律效力

### 开发流程原则

1. **需求驱动**：所有开发以需求清单为准
2. **规范约束**：必须遵循十步/八步开发流程
3. **API优先**：先定义接口再开发
4. **测试验证**：功能必须测试通过才算完成
