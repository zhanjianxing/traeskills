# Vibe Test - 测试验证

## 技能定位

**核心理念**：验证前后端功能是否满足需求，测试效果直到满意

## 测试流程

### Step 0: 确认项目目录

**动作**：确认测试代码在正确目录下

**目录结构**：
```
code/{项目名称}/
├── frontend/           # 前端代码
└── backend/           # 后端代码
```

### Step 1: 功能测试

**动作**：验证每个功能是否正常工作

**测试清单**：
- [ ] 页面能否正常打开
- [ ] 数据能否正常展示
- [ ] 增删改查是否正常
- [ ] 权限校验是否生效
- [ ] 错误提示是否友好

**测试方法**：
1. 启动前后端服务（在 code/{项目名称}/ 目录下）
2. 逐个功能测试
3. 记录问题

**话术**：
```
"开始功能测试。
测试结果：
- 登录功能：✅ 正常
- 列表展示：✅ 正常
- 新增功能：❌ 报错

发现1个问题，正在修复..."
```

### Step 2: 效果验证

**动作**：确认功能效果是否符合用户预期

**验证问题**：
```
1. 页面效果满意吗？
2. 交互体验流畅吗？
3. 数据展示正确吗？
4. 错误处理友好吗？
```

**话术**：
```
"功能测试完成。
请确认：
1. 页面效果满意吗？
2. 需要调整什么？

确认后继续下一步。"
```

### Step 3: 问题修复

**动作**：修复测试中发现的问题

**修复优先级**：
1. 功能性问题（功能不能用）
2. 体验问题（交互不流畅）
3. 视觉效果问题（样式不好看）

**分块规则**：
- 每次只修复1-2个问题
- 修复后让用户确认
- 确认后再修复下一个

### Step 4: 回归测试

**动作**：确保修复没有引入新问题

**回归检查**：
- 修复的问题是否真的解决了
- 修复是否影响了其他功能
- 整体功能是否仍然正常

## 关键原则

### 1. 项目隔离
- 测试代码在 code/{项目名称}/ 目录下
- 前端在 frontend/，后端在 backend/

### 2. 效果导向
- 功能能用是基础，效果满意是目标
- 用户说"可以"才算通过
- 用户说"不行"就继续改

### 3. 小步测试
- 每次只测1-2个功能
- 测完就确认，有问题就改
- 不要累积一堆问题一起处理

### 4. 及时修复
- 发现问题立即修复
- 不要等问题多了再处理
- 修复后立即验证

### 5. 用户参与
- 让用户参与验证
- 用户的反馈是最重要的
- 用户满意才算完成

## 测试场景

### 场景1: 功能测试
```
测试：用户登录功能
1. 输入正确账号密码 → 登录成功，进入首页
2. 输入错误密码 → 提示"密码错误"
3. 不输入账号 → 提示"账号不能为空"
4. 未登录访问 → 跳转登录页
```

### 场景2: 效果验证
```
效果验证：
1. 页面打开速度：< 2秒 ✅
2. 列表加载时间：< 1秒 ✅
3. 按钮点击反馈：有 ✅
4. 错误提示样式：美观 ✅
```

- "测试"
- "验证"
- "看看效果"
- "能不能用"
