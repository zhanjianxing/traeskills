# 外包报价新模式（AI驱动智能报价）

传统外包报价按人天/工时计算，在AI时代可以有更智能的选择。本技能根据客户类型智能匹配合适的报价模式。

> 💡 **AI时代人天估算核心观点**：AI不是只加快开发速度，而是**全流程**提升效率。从需求分析、方案设计、UI设计、开发、测试、部署上线到交付，每个环节都有AI辅助，**整体效率提升50-70%**。

## Step 1: 判断客户类型

在报价前，先判断客户属于哪种类型：

| 客户类型 | 特征 | 适合模式 |
|----------|------|----------|
| **传统型** | 明确要"做个软件"、关心工时、预算固定 | 传统固定总价 |
| **价值型** | 关心ROI、愿意为效果付费、愿意分享收益 | AI新模式 |
| **观望型** | 犹豫不决、想先看看效果 | 保守型报价 |

### 快速判断问题

```
如果客户说：
- "做个网站多少钱" → 传统型
- "能帮我提升多少业绩" → 价值型
- "先做看看效果" → 观望型
- "按人天怎么算" → 传统型
- "AI能帮我做什么" → 价值型
```

## Step 2: 根据类型报价

### 模式A：传统型客户 → 传统报价

这类客户就想要"买一个软件"，按他们熟悉的方式报价：

#### AI时代人天估算（全流程）

AI时代，人天估算不再只是"开发时间"，而是**从合同签订到项目上线的全流程**：

```
总人天 = 需求分析 + 方案设计 + UI设计 + 开发 + 测试 + 部署上线 + 交付
```

| 阶段 | 传统估算 | AI时代估算 | 说明 |
|------|----------|------------|------|
| **需求分析** | 1-2人天 | 0.5-1人天 | AI辅助需求文档生成 |
| **方案设计** | 1-2人天 | 0.5-1人天 | AI辅助技术方案 |
| **UI设计** | 3-5人天 | 1-2人天 | AI辅助生成设计稿 |
| **开发** | 10-20人天 | 3-7人天 | AI辅助代码生成，提升70%效率 |
| **测试** | 3-5人天 | 1-2人天 | AI辅助测试用例生成 |
| **部署上线** | 1人天 | 0.5人天 | 自动化部署 |
| **交付** | 1人天 | 0.5人天 | 文档自动生成 |

**AI效率系数**：
- 简单项目：0.3-0.4（效率提升60-70%）
- 中等复杂度：0.4-0.5（效率提升50-60%）
- 复杂项目：0.5-0.6（效率提升40-50%）

#### 人天计算公式

```
人天 = (传统估算人天 × AI效率系数) + 沟通协调 + 客户确认等待

示例（中等复杂度企业官网）：
- 传统估算：20人天
- AI效率系数：0.4
- AI辅助开发：20 × 0.4 = 8人天
- 沟通协调：2人天
- 客户确认等待：2人天
- 总计：12人天
```

**付款方式**：预付款30% + 尾款70%

### 模式B：价值型客户 → AI新模式

这类客户认可AI价值，愿意按价值付费：

#### 1. 价值定价法

```
报价 = 基础成本 + 价值分成 + 风险溢价
```

- **基础成本**: 实际开发成本（AI工具费用+人工审核+基础设施）
- **价值分成**: 项目成功后带来的收益分成（效率提升、业绩增长、成本节省）
- **风险溢价**: 项目难度/复杂度的风险补偿

#### 2. 里程碑付款模式

```
付款比例 = 30%（预付款） + 40%（中期交付） + 30%（验收通过）
```

#### 3. 效率对赌机制

```
实际报价 = 基础报价 × (约定效率 / 实际效率)
```

- 约定效率: 传统开发耗时的百分比（如30%）
- 实际效率: 实际完成时间/传统开发时间
- 提前完成：退还部分款项或收取奖金
- 延期完成：减免部分费用

#### 4. 成果共享模式

适用于能直接量化收益的项目：

```
报价 = 成本价 + 收益分成（通常5%-20%）
```

收益可以是：GMV增长、转化率提升、人力成本节省等。

### 模式C：观望型客户 → 保守报价

提供两种方案让客户选择：

| 方案 | 模式 | 价格 | 风险 |
|------|------|------|------|
| 方案A | 传统报价 | ¥XX,XXX | 低风险 |
| 方案B | AI新模式 | ¥XX,XXX起 | 共担风险 |

引导话术：
> "您可以选择传统方式报价，也可以选择按效果付费的模式，如果项目效果达到预期，您只需付基础成本，效果越好我们再分成。"

## 适用场景对照表

| 场景 | 客户类型 | 推荐模式 |
|------|----------|----------|
| 内部管理系统 | 传统型/观望型 | 传统报价 / 里程碑付款 |
| 电商/营销类项目 | 价值型 | 价值定价+成果分成 |
| AI产品/智能应用 | 价值型 | 成本价+长期分成 |
| 短平快项目 | 任何 | 固定总价+快速交付 |
| 复杂创新项目 | 观望型 | 风险共担+里程碑付款 |

## 输出格式

生成报价方案时，包含以下内容：

1. **客户类型判断**: 说明为什么选择这种报价模式
2. **项目概述**: 简短描述项目目标和范围
3. **报价模式**: 选择的定价模式及理由
4. **报价明细**: 各项费用的详细分解
5. **付款计划**: 阶段性付款安排
6. **风险约定**: 双方风险分担机制
7. **交付标准**: 每个里程碑的验收标准
8. **有效期**: 报价有效期限

## 注意事项

1. **不要强推**: 客户要什么模式就用什么模式，强推会引起反感
2. **提供选择**: 观望型客户给两种方案让他们选
3. **AI效率证明**: 如果用AI新模式，保留工具使用记录作为证据
4. **成果量化**: 在项目开始前与客户明确约定成果衡量指标
5. **退出机制**: 明确项目中断时的结算方式
6. **知识产权**: 明确代码和数据的归属权
7. **保密协议**: 添加保密条款保护双方利益

---

> 💡 **核心原则**: 客户要什么模式就給什么模式。人家就是来"买软件"的，别废话，直接按传统方式报价。
